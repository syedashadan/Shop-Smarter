1. Merge Sort (Divide and Conquer)

Stable, comparison-based sorting algorithm
Definition

Merge Sort is an efficient, comparison-based, divide-and-conquer algorithm that recursively divides an array into two halves, sorts each half, and merges the sorted sub-arrays into a single ordered list.

How It Works
  1. Divide: Find the midpoint mid = len // 2 and split the product list into Left and Right halves.
  2. Conquer: Recursively call merge_sort() on both halves until single-element lists remain.
  3. Combine: Merge the sorted sub-arrays by repeatedly picking the smaller product price.
Complexity Analysis
BestAverageWorstSpace
O(n log n) O(n log n) O(n log n) O(n)
Pseudocode
function mergeSort(arr):
    if length(arr) <= 1:
        return arr
    mid = length(arr) / 2
    left = mergeSort(arr[0..mid])
    right = mergeSort(arr[mid..end])
    return merge(left, right)

function merge(left, right):
    result = []
    while left and right not empty:
        if left[0].price <= right[0].price:
            result.append(left.pop(0))
        else:
            result.append(right.pop(0))
    return result + left + right
Viva Example Walkthrough on Sample Assignment Data:

Input: [₹45,000, ₹12,000, ₹65,000, ₹25,000, ₹18,000]

  • Divide: Left = [45k, 12k], Right = [65k, 25k, 18k]
  • Recurse Left: [45k] and [12k] merge into [12k, 45k]
  • Recurse Right: [65k] and [25k, 18k] → [25k, 18k] splits & merges to [18k, 25k] → merges with [65k] to [18k, 25k, 65k]
  • Final Merge: [12k, 45k] + [18k, 25k, 65k] → [12k, 18k, 25k, 45k, 65k]
Advantages
  • Guaranteed O(n log n) runtime even in worst case.
  • Stable sort (preserves relative order of equal prices).
  • Ideal for linked lists and external disk sorting.
Limitations
  • Requires O(n) auxiliary memory for merging.
  • Higher overhead for small in-memory arrays.
Real-World Usage

Used in Linux kernel (e.g. lib/list_sort.c), Python's Timsort hybrid, e-commerce distributed external sorting (e.g., millions of products from databases).

2. Quick Sort (Partitioning)

High-performance in-memory sorting algorithm
Definition

Quick Sort is an in-place divide-and-conquer algorithm that selects a "pivot" element and partitions the other elements into two sub-arrays, according to whether their price is less than or greater than the pivot.

How It Works
  1. Choose Pivot: Select a pivot element (e.g. middle element).
  2. Partition: Reorder products so all items with price < pivot come before it, and items with price > pivot come after.
  3. Recurse: Recursively apply the above steps to sub-arrays of smaller and greater items.
Complexity Analysis
BestAverageWorstSpace
O(n log n) O(n log n) O(n²) O(log n)
Pseudocode
function quickSort(arr, low, high):
    if low < high:
        pi = partition(arr, low, high)
        quickSort(arr, low, pi - 1)
        quickSort(arr, pi + 1, high)

function partition(arr, low, high):
    pivot = arr[high].price
    i = low - 1
    for j = low to high - 1:
        if arr[j].price < pivot:
            i = i + 1
            swap(arr[i], arr[j])
    swap(arr[i + 1], arr[high])
    return i + 1
Viva Example Walkthrough on Sample Assignment Data:

Input: [₹45,000, ₹12,000, ₹65,000, ₹25,000, ₹18,000]

  • Pivot Selection: Choose middle element ₹65,000 or last element ₹18,000.
  • Partitioning: Put prices < 18k ([12k]) on left, 18k in middle, > 18k ([45k, 65k, 25k]) on right.
  • Recurse Right: For [45k, 65k, 25k], choose pivot 25k → left: [], mid: 25k, right: [45k, 65k].
  • Final Concatenation: [12k] + [18k] + [25k] + [45k] + [65k] → [12k, 18k, 25k, 45k, 65k]
Advantages
  • Very fast in practice due to CPU cache locality and low constants.
  • Space efficient: requires only O(log n) call stack space.
Limitations
  • Worst case is O(n²) if an extreme pivot is picked continuously.
  • Not naturally stable.
Real-World Usage

Default in C's qsort(), JavaScript V8 sort for primitives, real-time gaming engines and financial matching systems.

3. Binary Search

Logarithmic-time search on sorted collections
Definition

Binary Search is an optimal search algorithm that finds the position of a target value within a sorted array by repeatedly comparing the target value to the middle element and halving the search space.

Prerequisite

Array MUST be sorted first! (In our project, we sort via Merge Sort first).

Complexity Analysis
BestAverageWorstSpace
O(1) O(log n) O(log n) O(1)
Pseudocode
function binarySearch(arr, target):
    low = 0
    high = length(arr) - 1

    while low <= high:
        mid = (low + high) / 2
        if arr[mid].price == target:
            return mid   // Found!
        else if target < arr[mid].price:
            high = mid - 1 // Search left
        else:
            low = mid + 1  // Search right

    return -1 // Not found
Viva Example Walkthrough (Search Target = ₹25,000):

Sorted Array: [0: ₹12,000, 1: ₹18,000, 2: ₹25,000, 3: ₹45,000, 4: ₹65,000]

  • Step 1: Low=0, High=4 → Mid = 2. Middle value = ₹25,000.
  • Check: Target ₹25,000 == Middle ₹25,000 → MATCH FOUND in 1 comparison (Best Case O(1))!
  • If searching ₹18,000: Step 1 Mid=2 (25k) → 18k < 25k (go left, High=1). Step 2: Mid=0 (12k) → 18k > 12k (go right, Low=1). Step 3: Mid=1 (18k) → Found in 3 steps!

Frequently Asked DAA Viva Questions

Binary Search relies on the monotonicity invariant: if the target is greater than the middle element, it is guaranteed to be in the right half only if the list is sorted. On an unsorted list, eliminating a half would discard potentially matching items, leading to incorrect results.

Merge Sort requires O(n) auxiliary space to hold the sub-arrays while merging them. In contrast, Quick Sort is an in-place sort that only uses O(log n) stack memory for recursive function calls.

When the pivot chosen is always the minimum or maximum element (such as choosing the first or last element of an already sorted array). This causes partitions of size 0 and n-1, creating a recurrence tree of depth n. Choosing the middle element or random pivot mitigates this.

Real-world CPU execution times fluctuate by fractions of a millisecond due to operating system thread context switches, CPU frequency scaling (thermal throttling or turbo boost), memory cache hits/misses, and background processes. This demonstrates why algorithmic analysis relies on asymptotic Big-O notation rather than raw clock time alone.
