Why Binary Search is O(log n) — Viva Concepts

1. Halving the Problem Space: At each iteration, Binary Search calculates \( \text{mid} = \lfloor \frac{\text{low} + \text{high}}{2} \rfloor \). By comparing the target against the middle element, exactly half the remaining search array is immediately discarded.

2. Mathematical Derivation: After \( k \) iterations, the size of remaining elements is \( \frac{n}{2^k} \). In the worst case, the search terminates when \( \frac{n}{2^k} = 1 \implies 2^k = n \implies k = \log_2 n \).

3. Linear Search vs Binary Search: In a linear search of 32 products, worst-case requires 32 comparisons. In Binary Search, \( \lceil \log_2 32 \rceil = 5 \) comparisons maximum! For 1,000,000 items, Linear Search takes up to 1,000,000 comparisons while Binary Search takes at most 20 comparisons!

4. Precondition Awareness: Because Binary Search relies on order transitivity (\( A[i] \le A[j] \)), running it on an unsorted list produces erroneous results. Hence pre-sorting via Merge Sort is mandatory.
