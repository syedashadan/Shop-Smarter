Why Performance Varies in Real Systems
1. Theoretical Complexity vs. Real Execution

Asymptotic notation (\( O(n \log n) \)) describes growth rate as \( n \to \infty \) ignoring constant factors (\( c \cdot g(n) \)). In practical execution on Python 3.11, constant factors such as function call overhead, list allocation, and memory cache misses heavily influence the measured clock time.

2. Memory Overhead of Merge Sort

Merge Sort requires auxiliary space \( O(n) \) to allocate sub-arrays during splitting and merging. Memory allocation in Python has a non-negligible cost, which can cause Quick Sort to execute faster for small to medium datasets.

3. Pivot Selection in Quick Sort

Quick Sort's worst-case time is \( O(n^2) \) if the pivot is repeatedly chosen poorly (e.g. smallest or largest element on sorted inputs). SmartShop selects the median/middle element to guarantee balanced partitions.

4. Micro-architectural Caching

Quick Sort performs in-place operations with sequential cache access, giving modern CPU L1/L2 data caches better hit rates than algorithms requiring dynamic allocation.
